# mirrorwise

[English version](README.md)

**Проверяет реестры пакетов из вашей сети, выбирает рабочее зеркало, безопасно переключает на него и возвращает всё назад, когда официальный реестр снова работает.**
Без зависимостей. При необходимости — один файл (`mirrorwise.pyz`). Python 3.9+.

```console
$ mirrorwise doctor pip
pip - pip / uv / Poetry (PyPI)
  ID               ДОВЕРИЕ    СТАТУС  ЗАДЕРЖКА  ДЕТАЛИ
  pypi             upstream   СБОЙ    100 ms    tls: connection dropped during TLS handshake
  yandex-pypi      vendor     ok      140 ms
  tuna-pypi        vendor     ok      420 ms
  ...
  НЕДОСТУПНО: официальный реестр (tls: connection dropped ...). Рабочее зеркало: yandex-pypi. Выполните: mirrorwise apply pip
```

> Вывод выше сокращён из [docs/demo.ru.txt](docs/demo.ru.txt). В этом файле часть 1 — настоящие проверки против локальных тестовых серверов, часть 2 — **смоделированные** результаты проб (планирование и работа с файлами настоящие). Это не измерение какой-либо реальной сети.

## Зачем

Реестры и зеркала ломаются так, что это неприятно диагностировать и утомительно обходить:

- `pip install` зависает или падает с ошибкой TLS, хотя сайт в браузере открывается.
- «Решение» — скопированный из статьи адрес зеркала, который вручную вписывают в четыре разных формата конфигов.
- Через месяц официальный реестр снова работает, а зеркало осталось в конфиге, и никто не помнит почему.
- В CI это выглядит как красная сборка, а не как понятное «реестр недоступен с этого раннера».

Публичные сообщения о такой картине в 2026 году (обрывы соединения с PyPI на этапе TLS из российских сетей 1–2 июня, ухудшение доступа к GitHub в мае и июле, Docker Hub в 2024) собраны со ссылками в [docs/research.md](docs/research.md). Там же написано, чего эти данные **не** доказывают.

mirrorwise — маленький скучный инструмент для этой ситуации: **измерить, решить, поменять одну вещь, оставить путь назад.**

## Что умеет

| Команда | Что делает |
|---|---|
| `mirrorwise list` | показать каталог зеркал (встроенный и ваш) |
| `mirrorwise probe [eco...]` | проверить, какие источники отвечают с этой машины, и на каком этапе ломаются (`dns`, `connect`, `tls`, `http`, `content`, `timeout`, `proxy`) |
| `mirrorwise doctor [eco...]` | проверить и вынести вердикт по каждой экосистеме. Код выхода `0` — всё хорошо, `1` — нужно действие, `2` — сломано. Удобно для CI |
| `mirrorwise status` | показать текущие настройки и управляет ли ими mirrorwise |
| `mirrorwise apply <eco>` | переключиться на лучший рабочий источник (сначала резервная копия, `--dry-run` — только показать) |
| `mirrorwise revert <eco>` | вернуть конфиг байт в байт |
| `mirrorwise env <eco>` | напечатать переменные окружения для CI (`sh`, `powershell`, `github`, `json`), не трогая файлы |
| `mirrorwise lint-data [--overlay] [файл]` | проверить JSON с зеркалами (`--overlay` — для ваших файлов `--data`) |

Экосистемы: **pip**, **npm**, **Go**, **Cargo**, **Docker**. Зеркала PyPI подходят и для uv и Poetry, но mirrorwise правит только собственный конфиг pip. Для uv команда `env` выдаёт ещё и `UV_INDEX_URL`; бэкенд `uv.toml` и поддержка Poetry — открытые задачи.

## Установка

pip может быть как раз тем, что сломано, поэтому способов несколько:

```bash
# 1. Один файл, без установки. Скачайте mirrorwise.pyz со страницы Releases:
python3 mirrorwise.pyz doctor

# 2. pipx / pip
pipx install git+https://github.com/NICE-EYES/mirrorwise
# или
pip install git+https://github.com/NICE-EYES/mirrorwise

# 3. Из клона
git clone https://github.com/NICE-EYES/mirrorwise && cd mirrorwise
PYTHONPATH=src python3 -m mirrorwise --help
python3 scripts/build_zipapp.py        # соберёт dist/mirrorwise.pyz
```

У mirrorwise нет зависимостей (только стандартная библиотека), поэтому скопированный `.pyz` работает на любой машине с Python 3.9+. Публикация на PyPI — в планах.

## Быстрый старт

```bash
mirrorwise doctor                     # что работает отсюда?
mirrorwise apply pip --dry-run        # показать diff, ничего не писать
mirrorwise apply pip                  # спросит подтверждение, сделает копию, запишет конфиг
mirrorwise status                     # проверить, что настроено
mirrorwise revert pip                 # откатить; то же делает и apply, когда официальный реестр снова здоров
```

Без терминала нужен `--yes` или `--dry-run`. `apply` требует явно указать экосистему или `--all`, чтобы случайно не изменить сразу пять инструментов.

Своё зеркало (например, корпоративный Nexus или Artifactory):

```bash
mirrorwise probe pip --url https://nexus.example.com/repository/pypi/simple/
mirrorwise apply pip --url https://nexus.example.com/repository/pypi/simple/ --yes
```

### CI

```bash
# GitHub Actions: печатает переменные только если официальный реестр нездоров
- run: python3 mirrorwise.pyz env pip npm go --format github >> "$GITHUB_ENV"

# любой shell
eval "$(python3 mirrorwise.pyz env pip npm go --format sh)"
```

Если официальный реестр здоров, `env` ничего не печатает (`--always` — напечатать всё равно). Переменные: `PIP_INDEX_URL` и `UV_INDEX_URL` для pip, `npm_config_registry` для npm, `GOPROXY` для Go. Cargo и Docker настраиваются файлами и настройками демона, поэтому `env` их не поддерживает.

## Как принимается решение

1. **Проба** каждого кандидата маленьким настоящим запросом (например, `pip/` у PyPI, метаданные `left-pad` у npm, `config.json` у sparse-индекса Cargo). Проверяется содержимое ответа, а не только код: captive-портал, отвечающий `200 OK` с HTML, считается сбоем.
2. При ошибке mirrorwise **заново диагностирует по этапам** на сырых сокетах и отличает сбой DNS, TCP-соединения, TLS и HTTP.
3. **Политика** (`selection.choose`):
   - официальный реестр здоров — остаёмся на нём;
   - здоров, но медленнее `--slow-ms` (по умолчанию 3000) и есть зеркало минимум вдвое быстрее — считается деградацией, выбираем зеркало;
   - недоступен — берём самое быстрое здоровое зеркало из разрешённых;
   - `--fastest` — самое быстрое из всех.
4. **План** (`apply`):
   - источник, который сейчас работает, не трогаем (нет «дрожания» между зеркалами);
   - зеркало, которое поставил сам mirrorwise, снимается (через revert), когда официальный реестр здоров;
   - сломанный пользовательский источник заменяется;
   - явный `--mirror` или `--url`, не прошедший пробу, отклоняется без `--force`.

### Уровни доверия

| Уровень | Смысл | По умолчанию |
|---|---|---|
| `upstream` | официальный реестр | да |
| `vendor` | компания, университет, облачный провайдер | да |
| `user` | ваш URL или overlay-файл | да |
| `community` | частные или неизвестные операторы | **нет**, нужен `--allow-community` |

## Модель безопасности

- Только https. `http://` отклоняется без `--allow-insecure` (для локальных тестов).
- Редиректы с `https` на `http` отклоняются.
- Конфиги пишутся атомарно, с резервной копией и манифестом в каталоге состояния (`MIRRORWISE_STATE_DIR` или `~/.local/state/mirrorwise`). `revert` возвращает исходные байты или удаляет файл, которого раньше не было. Откаты складываются в стек.
- Неудачная запись не оставляет «фантомной» записи о копии.
- Меняется только нужная настройка: `index-url` в `[global]` у pip, строка `registry=` в `.npmrc` (scoped-реестры не трогаются), помеченный блок у Cargo, ключ `registry-mirrors` в `daemon.json` у Docker, `GOPROXY` через `go env -w`.
- Если переменная окружения перекрывает файл (`PIP_INDEX_URL`, `npm_config_registry`, `GOPROXY`), mirrorwise предупредит, что в этой оболочке изменение не подействует.
- Прокси из окружения учитываются. `--no-proxy` их игнорирует.
- Cargo: чужая секция `[source.crates-io]` останавливает изменение явным конфликтом, а не перезаписывается.

### Зеркало — это третья сторона

Зеркало может отдать изменённые файлы. mirrorwise не может сделать это безопасным. Риск снижают так: брать зеркала уровня `vendor` (по умолчанию), держать lock-файлы с хешами (`pip install --require-hashes`, integrity в `package-lock.json`, `go.sum`, `Cargo.lock`) и откатываться после инцидента — `apply` делает это сам.

## Данные о зеркалах

Каталог — обычный JSON: [src/mirrorwise/data/mirrors.json](src/mirrorwise/data/mirrors.json). Важные оговорки:

- Каждая запись — **кандидат**, взятый из публичных статей и документации вендоров, со ссылками-доказательствами. Сейчас все помечены `"confirmed": false`: окружение автора не могло проверить их из затронутой сети. Источник истины в момент работы — проба, а не список.
- Добавлять и отключать записи локально можно overlay-файлом (`--data FILE` или `~/.config/mirrorwise/mirrors.json`). Пример: [examples/mirrors.corporate.json](examples/mirrors.corporate.json).
- `mirrorwise lint-data` проверяет встроенный файл (только https, доказательства обязательны, пока не `confirmed`, уникальные id, URL Cargo с `sparse+`). `mirrorwise lint-data --overlay FILE` проверяет ваш overlay-файл и ловит опечатки в названиях экосистем и в `disable`.
- Чтобы добавить зеркало во встроенный каталог, используйте шаблон issue **Mirror request** и приложите вывод `mirrorwise probe`.

## FAQ

**Нужен ли root?** Для pip, npm, Go и Cargo нет: это пользовательские файлы. В Linux файл Docker по умолчанию — `/etc/docker/daemon.json`, там нужен `sudo` (в macOS и Windows — `~/.docker/daemon.json`). Ошибка прав выводится как ошибка, наполовину записанных файлов не остаётся. Под `sudo` копия хранится в каталоге состояния root, поэтому откатывать тоже нужно `sudo mirrorwise revert docker`. Демон mirrorwise не перезапускает, только напоминает. Другой файл можно указать через `--config-path`.

**Это обход блокировок?** Нет. Это не VPN и не прокси. Инструмент помогает, только если легитимное зеркало доступно из вашей сети.

**Почему не просто `pip config set global.index-url ...`?** Можно и так. mirrorwise добавляет измерение, решение, резервную копию, автоматический путь назад и одинаковое поведение для пяти инструментов.

**Что с базой контрольных сумм Go?** mirrorwise выставляет только `GOPROXY` (как `<url>,direct`) и никогда не трогает `GOSUMDB`, `GONOSUMDB` и `GOFLAGS`. Если недоступна сама база контрольных сумм, ошибку выдаст `go`; не «чините» её отключением проверки.

**Поддерживаются ли uv / Poetry / pnpm / Yarn?** `apply` правит только конфиг pip. У uv своя конфигурация (`uv.toml`): получите `UV_INDEX_URL` через `mirrorwise env pip --format sh` или помогите с бэкендом `uv.toml` (good first issue). Poetry хранит источники в `pyproject.toml` и не поддерживается. pnpm и Yarn classic читают `.npmrc`, который правит npm-бэкенд (в v0.1 с ними не тестировалось). Yarn Berry имеет свой конфиг и пока не поддерживается.

**Есть ли телеметрия?** Нет. Единственный сетевой трафик — пробные запросы к адресам из каталога (и вашему `--url`).

**Каталог помечен `confirmed: false`. Почему ему доверять?** Не нужно доверять вслепую. Сначала `probe`, оставайтесь на уровне `vendor`, а поправки присылайте через шаблон issue.

## Ограничения (v0.1)

- Хостинг git (`git clone`, релизы GitHub) не покрывается. Это другая задача с другими способами решения.
- Встроенные данные о зеркалах невелики и не подтверждены (см. выше). Для других регионов нужны вклады сообщества.
- apt/yum/Homebrew, Maven/Gradle, NuGet, Composer, RubyGems пока не поддерживаются. См. [docs/good-first-issues.md](docs/good-first-issues.md).
- Скорость измеряется по маленькой выборке и годится для ранжирования, а не для бенчмарков.
- Проба проверяет индексный адрес. Зеркало PyPI, которое не переписывает ссылки на файлы, может зависеть от `files.pythonhosted.org` при самой загрузке, поэтому зелёная проба необходима, но недостаточна.

## Планы

Бэкенд `uv.toml`, Maven/Gradle, Composer, RubyGems, Yarn Berry, NuGet, git `insteadOf` для зеркал GitHub, автодополнение в shell, подписанная лента данных сообщества, новые языки. Подробности и good first issues: [docs/good-first-issues.md](docs/good-first-issues.md).

## Разработка

```bash
PYTHONPATH=src python3 -m pytest tests -q     # 107 тестов, сеть не нужна
PYTHONPATH=src python3 -m unittest discover -s tests -t .
python3 scripts/build_zipapp.py                # dist/mirrorwise.pyz
python3 scripts/demo.py ru > docs/demo.ru.txt  # перегенерировать демо
```

Тесты используют локальные фикстурные серверы (здоровый, обрывающий TLS, captive-портал, «чёрная дыра»), поэтому работают офлайн. См. [CONTRIBUTING.md](CONTRIBUTING.md).

## Аналоги и благодарности

Похожие инструменты существуют и заслуживают внимания: [chsrc](https://github.com/RubyMetric/chsrc) (C, GPL-3.0, гораздо больше целей), [nrm](https://github.com/Pana/nrm) (реестры npm). mirrorwise написан независимо, кода у них не заимствует и отличается акцентами: диагностика этапа сбоя, политика «сначала официальный реестр» с возвратом, резервные копии и откат, режим для CI.
